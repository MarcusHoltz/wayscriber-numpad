Numpad-driven tool switching for screen annotation on KDE Plasma (Wayland). wayscriber does the drawing. Your numpad is the toolbox. Turn on Drawing Mode from the app menu and KP1-KP0 become overlay, undo/redo, three pens, a highlighter, an eraser and a light passthrough; turn it off and they type digits again. Nothing is permanently remapped.

The numpad only does this while Drawing Mode is on. Before that, and after you turn it off, it types normal digits. Keep Num Lock on: without it KP2-KP7/9/0 send arrows and Home/End, not digits. keyd bindings are added on start and reset on stop, so number entry is never permanently lost.

keyd rows are remapped globally while Drawing Mode is on: KP1 & KP8 work even with the overlay hidden (and with Num Lock off), and only turning Drawing Mode off hands them back. overlay rows aren't remapped at all: they're wayscriber's own [keybindings], which only fire while the overlay is shown and holds keyboard focus.

What install does, in order
01

keyd, wired

On Arch, Debian and Ubuntu, keyd comes from the distro repo (Debian and Ubuntu name the binary keyd.rvaiya; the script calls that). Fedora has no package, so keyd v2.6.0 is built in the same container and installed with make install PREFIX=/usr. Then you're added to the keyd group and its service is enabled (sudo). Run newgrp keyd afterwards, or just log out and back in.

02

Runtime libraries

On Arch, the exact list from wayscriber's own PKGBUILD: cairo wayland pango libxkbcommon gtk4 gtk4-layer-shell libadwaita wl-clipboard grim slurp. Debian and Fedora get the same libraries under their own package names via apt / dnf (Fedora adds make for keyd). All sudo.

03

wayscriber, built in Docker

One Dockerfile for every distro: a Debian 13 container (glibc 2.41, GTK 4.18) installs the rust toolchain pinned by upstream's rust-toolchain.toml, clones the repo and runs cargo build --release with default features. Built against the oldest supported glibc, the same binary runs on Arch, Ubuntu and Fedora. Only the finished binary (and the keyd tree Fedora uses) crosses back out, into ./dist/. The toolchain and the clones never touch your host. The :Z bind-mount label is for Fedora's SELinux.

04

Binary, no sudo

The binary lands in ~/.local/bin/wayscriber. No service is created for wayscriber and nothing autostarts: it only runs while Drawing Mode is on.

05

config.toml

Installed to ~/.config/wayscriber/. This repo's copy is the source of truth: if the installed one differs, the plan says so, the old copy is saved to ~/.local/state/wayscriber-numpad/config-backups/ and replaced, and a running Drawing Mode is restarted to load it. status warns when they differ.

06

The keyd bridge

/etc/keyd/wayscriber.conf (sudo) plus ~/.local/bin/wayscriber-ctl.sh, the bridge keyd, running as root, calls to run wayscriber as you. Its HOME comes from your passwd entry, not a hardcoded /home/$USER.

07

The Drawing Mode app, no sudo

~/.local/bin/wayscriber-numpad (the on/off switch), ~/.config/systemd/user/wayscriber-numpad.service (never enabled: no [Install] section, stops at logout) and wayscriber-numpad.desktop, the app-menu entry.

Use it

No terminal needed. Open the app menu, click Drawing Mode: the wayscriber tray icon appears and a popup says to press 1. Press 1 to draw, 1 again when done. Click Drawing Mode again to turn it off. Right-click offers Turn On / Turn Off, and it can be pinned to the panel. It never starts on its own and turns itself off at logout.

Built for screen recording

Only the drawing shows. This repo's config hides wayscriber's status bar, zoom chip and floating board badge, and turns off its tips, capability warnings, preset toasts, presenter toast and update notifications. Set any back to true in the repo's config.toml and re-run install. Drawing Mode's own on/off popups stay on; they appear only when switching, never while drawing (POPUPS= in the switch script).

Customize

Edit this repo's config.toml, then run ./wayscriber.sh install to push it and restart Drawing Mode. Direct edits to ~/.config/wayscriber/config.toml get replaced (after a backup). The [presets.slot_1..5] blocks decide what KP9 / KP0 / KP4 / KP5 / KP6 select (tool, color, size, marker_opacity…); the [keybindings] block remaps KP2-KP7/9/0. KP1 and KP8 are the exception: they're the keyd bindings, set under keys-on in generate_toggle() in wayscriber.sh, and limited to the ten action names wayscriber's TrayAction actually accepts.

Uninstall

./wayscriber.sh uninstall asks first, turns Drawing Mode off, then removes the Drawing Mode app (launcher, switch, systemd unit), the keyd config, the bridge script and only what its own receipt file shows it installed. A keyd setup you already had survives untouched. wayscriber itself and its runtime libraries stay on purpose; the script prints the exact commands to remove those too, instead of running them.

the engine under the keys.

wayscriber, the whole machine

wayscriber is a live screen annotation and presentation tool for Linux, written in Rust. One keybind puts a drawing layer over the screen: you can annotate, present, zoom, capture, and then hide the layer again. This repo wires ten of its ~130 actions onto your numpad; everything on this stretch of the page is what's actually running underneath. (Their homepage is an app too: press \ there and you can draw on it. This one answers to your number keys.)

what's actually running.

›wayscriber idle

  1. the full drawing toolkit kp 4·5·6·9·0

    pen, highlighter and eraser: smooth freehand ink on a layer above every window, sizes to 50.

  2. shapes & numbered arrows

    lines, rectangles, ellipses, fillable polygons, and arrows with auto-numbered labels, step markers and blur. select, move and restack any of them.

  3. text & sticky notes

    multiline text you can place, edit, move and restyle, plus sticky notes for the things that must not be missed.

  4. radial menu at the cursor

    hold middle-click: a fixed eight-way compass of tool glyphs, recent colors and an outer size ring. move the pointer, release, done.

  5. command palette

    ctrl+k fuzzy-searches every action, with icons and category headers. reopen recents, save preset slots, edit shortcuts in place.

  6. boards & pages

    transparent overlay, whiteboard, blackboard, blueprint or corkboard. separate pages per board, auto-contrast pens, ctrl+shift+1..9 jump slots, space+drag to pan.

  7. zoom & presenter mode

    zoomit-style ctrl+alt+scroll zoom with lock and pan. a live-percent chip sits in the corner with zoom-out, fit and lock (this repo's config hides it for recording).

  8. light passthrough kp8

    clicks pass through the overlay while your drawings stay visible: work under your notes. needs a layer-shell compositor; KDE Plasma has it.

  9. capture & ocr

    region, window or full screen to the clipboard or a png. select on-screen text, run ocr, copy the result. The overlay stays open.

  10. input hud

    ctrl+shift+k paints your keystrokes and clicks on the screen, for demos and screencasts. held keys collapse into a ×n counter.

  11. sessions that survive kp1

    boards, undo history and tool state persist per monitor across restarts: compressed, backed up, auto-recovered after a crash.

fast by default.

ink that keeps up with your hand

Native Wayland, native code: a Rust binary drawing directly to layer-shell surfaces. No Electron, no webview, no compositor trick. Vsync is off with a 120 FPS cap for low-latency ink; in local input-to-commit measurements, p95 and p99 stayed near 8-9 ms during continuous drawing.

Always warm. wayscriber runs as a daemon: the overlay opens with no cold start and no splash screen. Tunable: turn vsync on for tear-free rendering or quieter fans, and raise the cap to 144 or 240 on a fast display.

this latency is input-sample → wayland surface commit, not end-to-end display latency. set WAYSCRIBER_PERF_LOG=1 to measure it yourself.

config.toml
# config.toml
[performance]
buffer_count = 3          # balanced buffering
enable_vsync = false      # lower drawing latency
max_fps_no_vsync = 240    # for a fast display + GPU
ui_animation_fps = 60     # smoother UI effects
defaults: 120 fps drawing · 30 fps ui effects · buffer_count 3 (more buffers use more memory and don't raise the cap).

“wayscriber is shared as a gift exchange, not a contract.”

free, MIT-licensed, and in active development. no guaranteed timelines, no guaranteed support. contributions welcome, especially compositor tests, multi-monitor reports, and new drawing tools.

upstream ships native packages for Debian, Ubuntu, Fedora, the AUR and Nix. this repo builds the same binary from source in Docker (no AUR helper, nothing touching your host but the finished binary) and points ten numpad keys at it. that part is up in section 03.

05

If something's off.

seven known shapes of "off"

"needs a Wayland session"

You're in KDE's X11 session (XDG_SESSION_TYPE=x11). Log out, pick Plasma (Wayland) in SDDM, log back in. wayscriber's layer-shell overlay cannot appear on X11; ./wayscriber.sh status prints the detected session.

Numpad keys do nothing

Check Num Lock is on (KP2-KP7/9/0 need it). Watch the raw layer with sudo keyd monitor: press the keys and confirm keyd sees kp0-kp9. Then ./wayscriber.sh status to check keyd is up and Drawing Mode is on.

Overlay won't show after KP1

journalctl --user -u wayscriber-numpad.service -n 50 holds wayscriber's log. Also check ./wayscriber.sh status.

Drawing Mode didn't start

Nothing was changed; the numpad still types numbers. ./wayscriber.sh start (or the popup) names the likely cause: another wayscriber already running (exit 75), keyd not running, or no Wayland session. Otherwise log out and back in (e.g. just added to the keyd group). A hung start or stop gives up after 20 s / 5 s.

Overlay looks blurry on KDE

The "Better Blur" desktop effect blurs layer-shell surfaces, a documented wayscriber × KWin interaction, not a bug in this wiring. The fix is the window-rule exclusion in wayscriber's own troubleshooting docs.

keyd itself crashed

systemctl status keyd · journalctl -u keyd. This wiring only ever calls keyd bind / keyd bind reset, and the reset runs when Drawing Mode stops, even after a crash, so it never leaves the daemon in a half-bound state.

Fedora: keyd denied by SELinux

The build bind mount already carries :Z and install runs restorecon over the source-built keyd files. If keyd is still denied, check sudo ausearch -m avc -ts recent before blaming the numpad wiring.
